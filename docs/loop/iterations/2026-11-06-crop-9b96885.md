# 2026-11-06 crop: crop_png and a refusing `rect` on bevy_fairy/screenshot (issue #15)

## Summary
`bevy_fairy::crop_png` cuts a rectangle out of PNG bytes, and `bevy_fairy/screenshot` and the
`screenshot` tool take a `rect` that cuts through the same rule (`crop::crop_view`). It replaces
`region`, which clamped a rectangle that ran off the picture and so answered a picture of a different
place without saying so.

## Change: crop_png and `rect`
Plan: one bounds rule in `src/crop.rs`, used by `crop_png` and by `encode_capture`; `rect` replaces
`region` in the plugin and the server; `bevy_fairy/capture` reports `picture` · Files: `src/crop.rs`,
`src/lib.rs`, `Cargo.toml` (`crop` feature), `src/plugin/screenshot.rs`, `src/server/mcp_tools.rs`,
docs · Goal: the issue's six acceptance items · Proof: `tests/crop.rs` (items 1-5),
`plugin::screenshot::tests::a_screenshot_rect_is_the_crop_crop_png_makes_of_the_same_picture` (item 6).

Assumed decisions (recorded on the issue): `CropRect`, not `Rect` (Bevy's prelude `Rect` is in every
consumer's scope); `rect` replaces `region` rather than living beside it (one crop rule; breaking,
0.13.0); `ScreenshotParams` is `deny_unknown_fields`, so `region` is refused instead of ignored.

Failing first: `tests/crop.rs` did not compile on 9c4a7c0 (`unresolved imports bevy_fairy::crop_png,
bevy_fairy::CropRect`); 5/5 pass with `--no-default-features --features crop`.
